# ADR-0015: 1.1 additive batch — close the human-in-the-loop return path

**Status:** Accepted **Date:** 2026-06-06 **Deciders:** Kernel maintainers

## Context

1.0 froze the escalation/audit surface validated by three consumers (UCC, CxO, CVVE). CVVE — the first and
only consumer to drive `EscalationRung.HumanHandoff` for real — built its whole product (a
Verification-&-Validation-as-a-Service platform) on the kernel across six slices and, by design, fed back
ergonomics friction as **additive 1.1 candidates** rather than as 1.0 breakage (see
`agentic-doc-validation/docs/KERNEL_FEEDBACK.md`). Three items recurred and became concrete once CVVE built
its `/override` reviewer API and durable audit ledger:

1. **The handoff result drops the candidate.** When `HumanHandoff` fires, the policy returned a fresh
   `UNAVAILABLE` carrying only `{escalation, queue}` — not the candidate attempt's `data` (e.g. the field
   errors). CVVE had to **recompute** the validation to give the reviewer context.
2. **The return trip is unaudited.** The kernel modelled the *handoff out* but not the *return*: a human's
   approve/reject/correct produced no `AgentEvent`, so it landed only in the app's own ledger, never in the
   kernel audit trail — splitting the compliance story.
3. **Resume was hand-rolled.** "Apply the correction and re-emit a terminal decision" was entirely app-owned;
   every HITL consumer would re-derive the same re-run + close-out shape.

The kernel models the *decision*; the app models the *plumbing* (the boundary ADRs 0009/0013 and CVVE slices
4–6 repeatedly confirmed). These three items sit exactly on the decision boundary, so they belong in the
kernel — and all three can be done **additively**.

## Decision

Ship a focused, non-breaking **1.1** batch:

**(a) `HumanHandoff` carries the candidate.** `EscalationPolicy`'s handoff rung now copies the last candidate
attempt's payload — `answer`, `evidence`, `links`, `rationale`, and `data` — into the returned result, then
overlays the `{escalation, queue}` routing keys. The parked case is self-describing; the consumer stops
recomputing. **Additive:** the two routing keys 1.0 emitted are still present, so existing readers are
unaffected; the result is strictly richer.

**(b) `HumanDecided` audit event.** A new `AgentEvent` variant
`HumanDecided(capabilityId, epochMillis, decision, reviewer, reference)` records a reviewer's terminal
decision in the same stream as the machine `AgentCompleted`. Keys/summaries only (ADR-0008): `decision` is a
short app-defined label (the kernel stays neutral — e.g. `APPROVE`/`REJECT`/`CORRECT`), `reviewer` is an
id/handle, `reference` is an opaque correlation id (e.g. the request/case id). No corrected values, no record
contents.

**(c) `SyncOrchestrator.resume(request, ctx, decision, reviewer, reference)`.** Blesses the round-trip:
re-dispatch the corrected request through the normal pipeline (resolve → escalate → one `AgentCompleted`),
then emit one `HumanDecided`. The caller still builds the corrected request and supplies confidence that
clears the threshold (a human verified it) — the kernel stays neutral about correction semantics and only
owns the audited round-trip. A terminal approve/reject that does **not** re-run needs no orchestration: emit
`HumanDecided.of(...)` on the sink directly.

**Deferred:** the slice-5 "soft" idea of **per-capability escalation posture** (so a capability like CVVE's
`extract`, which must never escalate, need not neutralise the global `EscalationPolicy` via a `0.0` threshold).
It is a fine future addition but not part of this batch — today's single-policy default plus a one-line
threshold workaround is acceptable, and the change would touch `CapabilitySpec`/policy resolution, which
deserves its own ADR if a second multi-capability consumer wants it.

## Non-breaking analysis

- **(a)** Only enriches a `Map`/result fields; no signature change. The `AgentResult` canonical constructor
  is untouched.
- **(b)** Adds a permitted type to the sealed `AgentEvent`. Audited: there is **no exhaustive `switch` over
  `AgentEvent`** anywhere in the kernel, and all three consumer audit sinks
  (`UCC LoggingAuditSink`, `CVVE LoggingAuditSink`, `CVVE PostgresAuditSink`) dispatch with `instanceof`
  guards — so an unrecognised variant is simply ignored, both at runtime and on recompile against 1.1.
- **(c)** Adds a new public method to `SyncOrchestrator`; no existing signature changes.

No 1.0 type's shape changed; six consumer slices' behaviour is preserved. Consumers opt in by bumping to 1.1
when convenient (they resolve the kernel from `~/.m2` / GitHub Packages; nothing forces an upgrade).

## Consequences

- A HITL consumer gets a self-describing parked case, a unified machine-plus-human audit trail, and a blessed
  resume entry point — deleting app-side recompute and the hand-rolled round-trip.
- The sealed `AgentEvent` has now been extended once; the precedent is that observability variants are
  open-ended and sinks must tolerate unknowns (the `instanceof`-guard convention, not exhaustive switches).
- Full kernel reactor stays green (53 tests). CVVE can later simplify `ValidationService`/`ReviewService`
  onto these once it bumps to 1.1 (tracked as optional follow-up; not required).
